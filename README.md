# ESP32-WROOM-32 + INMP441: локальная активация и Assist

Ветка **`experimental/esp32-wroom32`**. Это отдельная прошивка для классического
ESP32-WROOM-32 (плата ESP32 DevKit с CH340/USB Type-C), не для Voice PE.
Ветка `dev` и прошивка Voice PE не изменяются.

Первый этап (локальное обнаружение «Окей, Набу») проверен пользователем.
Второй этап: после фразы ESP32 останавливает локальный детектор, передаёт
микрофон голосовому конвейеру HA, получает распознанный текст/результат и затем
возвращается к ожиданию активации. В лог по-прежнему выводится **`1`**.

Динамик пока не подключён: **звукового ответа нет**, текст ответа выводится в лог.
Часов, таймерной индикации, радионяни и звонков в этом конфиге нет.
Прежний YAML часов сюда переносить не нужно.

## Подключение INMP441

Отключите питание перед подключением.

| INMP441 | ESP32-WROOM-32 |
| --- | --- |
| VDD / VCC | **3V3**, не 5 В |
| GND | GND |
| SCK / BCLK | GPIO26 |
| WS / LRCL | GPIO25 |
| SD / DOUT | GPIO33 |
| L/R | GND — левый канал |

Не оставляйте L/R неподключённым. Надпись `SD` на микрофоне — выход данных,
его нужно подключить к входу ESP32. CH340 — USB–UART, в обработке звука не участвует.

## Прошивка через Git-пакет ESPHome

В ESPHome Device Builder создайте/замените конфигурацию именно этой ESP32-платы:

```yaml
substitutions:
  name: esphome-web-619b9c
  friendly_name: ESP32 Microphone

packages:
  wroom_microphone:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: experimental/esp32-wroom32
    files:
      - esp32-wroom32.yaml
    refresh: always

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

При необходимости задайте своё имя устройства. Первую установку выполните
по USB на WROOM-плату. В дальнейшем можно обновлять OTA через ESPHome.
Если в вашей текущей конфигурации используется шифрование API, сохраните свой
блок `api.encryption` локально; ключи в публичный репозиторий добавлять не надо.

`home-assistant-voice.yaml` в этой ветке также включает минимальный WROOM-пакет,
но явное имя `esp32-wroom32.yaml` помогает не спутать его с прошивкой Voice PE.

## Проверка

Откройте логи ESPHome, дождитесь запуска `micro_wake_word` и скажите «Окей, Набу».
Ожидаемая строка:

```text
[I][wake_word:...]: 1
```

Фраза определяется на самой ESP32. Для следующего за ней голосового запроса
нужны подключение устройства через интеграцию ESPHome в HA и настроенный Assist.
В настройках устройства выберите тот же голосовой ассистент, что у Voice PE:
распознавание речи (например Whisper), агент диалога (HA Dialog UI, если используете
его в своём конвейере) и синтез речи. Команда обрабатывается в выбранном конвейере,
без жёстко заданных текстов «включи свет» и прочих команд в прошивке.

Скажите «Окей, Набу», затем короткую команду. В логе ожидаются:
`Listening for command`, `Recognized command: ...`, `Response text: ...`,
`Assist request ended`, затем новый запуск детектора. Текст ответа появляется,
если HA дошёл до стадии TTS; выполненная команда может не иметь озвучиваемого ответа.
При отключённом HA останется локальная детекция, а в логе будет предупреждение,
что Assist недоступен. Wi-Fi задаётся локально.

## Ограничения первого этапа

WROOM-32 обычно не имеет PSRAM. Для этого эксперимента оставлена только одна
модель, без VAD и голосового диалога. ESPHome может использовать внутреннюю RAM,
но успешная сборка не гарантирует, что памяти и скорости хватит на вашей плате.
При нехватке памяти появится ошибка выделения буферов/tensor arena; при недостатке
скорости — сообщения переполнения или потери аудио. Сначала проверяем эти логи,
а затем постепенно добавляем функции.

Это не готовая замена Voice PE и не обещание такого же качества распознавания.
На реальной WROOM-плате прошивку ещё нужно проверить.


## Если нужна «Алиса» вместо «Окей, Набу»

Добавьте в локальный блок substitutions:

```yaml
  wake_word_model: https://raw.githubusercontent.com/mikhailhimei/home-assistant-voice-pe/dev/models/alisa.json
```

Это замена модели с последующей перепрошивкой, не загрузка двух моделей сразу.


## Если нет реакции

Раз в 10 секунд строка `wroom_status` показывает, запущены ли микрофон и детектор.
При наличии аудиоданных раз в 5 секунд строка `mic_audio` показывает число
сэмплов в секунду и уровень звука `peak16` / `mean_abs16`. Сами аудиозаписи
никуда не отправляются.

- `detector_running=0` — детектор не запустился; проверьте соседние сообщения
  о памяти. Кнопка **Start wake detection** повторяет запрос запуска.
- `microphone_running=0` — захват звука не запущен.
- Нет `mic_audio` — не приходят аудиоблоки.
- `samples_per_s` около 16000, но `peak16=0` даже при речи — проверьте питание,
  SD, SCK/WS и L/R. При L/R=GND должен быть левый канал.
- Уровень реагирует на речь, но детекций нет — дальше проверяем модель,
  усиление и скорость обработки; это ещё не доказательство неисправности микрофона.

Порог экспериментального профиля — `0.69`, как у умеренной чувствительности
модели Okay Nabu в нашем профиле Voice PE. Больше чувствительность может увеличить
число ложных срабатываний. Параметры можно переопределять в substitutions:

```yaml
  microphone_channel: left
  microphone_gain: "1"
  wake_word_probability_cutoff: "0.69"
```


## Память и последовательная работа

Перед отправкой команды локальный детектор полностью останавливается и освобождает
свои рабочие буферы. После окончания Assist он запускается заново. Одновременной
работы распознавания активации и записи команды в этом профиле нет.
Во время запроса повторная активационная фраза не прерывает команду.
На зависший запрос установлен сторожевой тайм-аут 60 секунд.
Второй этап требует проверки на плате: новые аудиобуферы Assist тоже занимают RAM.
Если будут ошибки выделения памяти, пришлите `wroom_assist` и соседние ошибки ESPHome.
Логи распознанной команды и текста ответа могут содержать личную информацию.
